# Game Launch Site — final build prompt

Scroll-scrubbed hero, operative select, pinned horizontal world tour

Palette: void black, gunmetal grey, and one irradiated acid green that only ever appears as signal — the active selection and the wishlist call to action. Nowhere else. Build a single-page launch site for a fictional co-op extraction shooter set aboard a derelict orbital station. It should feel like the cold open of a game trailer, not a storefront.

The footage has already been generated and sits in the ./footage/ directory. All eight clips are 1920x1080 and exactly 8 seconds long: hero.mp4 (the corridor push that gets scrubbed), op1.mp4 through op4.mp4 (the four operative turns, loopable), and plate1.mp4 through plate3.mp4 (the three environment plates, loopable). Do not generate any footage and do not call any video generation API. Confirm the clips with ffprobe before building. The descriptions below tell you what each file contains so you know what you're building around.

The hero clip (footage/hero.mp4): a slow, perfectly even push down the central corridor of a derelict space station toward a single cold light source at the far end. Emergency lighting only — thin strips of pale green along the floor line, everything else falling to black. Dust and small debris drifting weightless through the beam. Frost on the panel seams. No people, no movement other than the drift and the push. Locked mechanical dolly, no shake — this clip is scrubbed by scroll and any wobble will read as jitter. Deep blacks with no lift, heavy but fine grain.

The four operative clips (footage/op1.mp4 to op4.mp4), one per playable character: each a slow turn from profile to camera, waist-up, standing in that same corridor darkness. One hard pale rim light from behind-left, faces half-lost in shadow, a faint green edge where the suit catches the emergency strip. Different silhouette per operative — bulk, lean, rigged with gear, cloaked — same framing, same light, same grade. Loopable.

The three environment plates (footage/plate1.mp4 to plate3.mp4) for the world section: a shattered hydroponics bay with plants grown wild in zero-g, a cargo hold with containers drifting loose, an observation deck with a slow planet-rise through fractured glass. Locked-off camera, minimal movement — drift, dust, the planet inching up. Loopable, same grade.

Then build the site around the footage.

Pure black page, bone white type, and every trace of colour coming from the footage and the two permitted uses of acid green. Display face is Big Shoulders at its heaviest weight, condensed and set enormous in full caps, tracking tight, cropped by the viewport edge on purpose — it should read like stencilled hull markings. Labels and HUD copy in IBM Plex Mono, small, uppercase, wide-tracked, with the occasional bracketed status tag — [SIGNAL LOST], [04 OPERATIVES] — used sparingly as punctuation, not decoration. The collision between a brutal condensed display and a cold mono is the type idea; don't soften it with a third face.

Give the display type a single-pixel acid-green ghost offset on one side only — barely perceptible, a phosphor bleed rather than a glitch effect. No animated glitching, no RGB-split shudders, no scanline gimmicks. The restraint is what keeps it from looking like every other game site.

Load Big Shoulders and IBM Plex Mono from Google Fonts. Do not fall back to Inter, Helvetica or a system stack — if a face won't load, pick the nearest alternative of the same character and flag the swap in your final summary. Size everything with clamp() so the scale holds from phone to ultrawide.

Overlay a tiling noise texture at very low opacity across the whole page. Pure black gradients band into visible stripes on most displays and this dithers them out, and the same layer doubles as grain tying the interface to the footage. Soft vignette so the frame edges fall off rather than ending flat.

Install Lenis for smooth scroll, duration around 1.2. One easing curve for entrances, cubic-bezier(0.16, 1, 0.3, 1), one for exits, cubic-bezier(0.7, 0, 0.84, 0), and nothing linear. Text reveals use a per-line clip-path mask with the lines rising into place on a stagger; no opacity-only fades anywhere on this page.

Hero, scroll scrub: the corridor push has to be visible the instant the page lands, so the hero starts in an idle state with the clip playing slowly on its own, and the moment the visitor makes their first scroll input it hands over to scroll control and they're driving the push themselves. Ease that handover so it doesn't jump. Pin the section and scrub the clip to scroll position, full-bleed. Because the clip is only 8 seconds, give the pinned section a scroll length that makes the scrub feel unhurried — the visitor should take noticeably longer to scroll through it than the clip would take to play. The game title sits over the corridor in the display face and tightens its tracking very slightly as the camera closes on the light, as if the push is compressing it. The idle playback and the scrub both run off the same preloaded frame sequence, so the handover is just a change in what drives the frame index. A mono loader line — [ESTABLISHING LINK — 47%] — stays up until every frame is ready.

Operatives, select rows: four stacked rows, each an operative callsign in the display face. On hover, that operative's clip fades up full-bleed behind the rows and scrubs through the turn as the cursor traverses the row horizontally; the active callsign takes the acid green with a soft phosphor bleed behind the letters, every other row dropping to low-contrast gunmetal. On mouse-out the clip holds its frame for a beat, then fades. One mono spec line per operative — role, loadout, one flaw — revealed under the active callsign with the clip-path mask. Slow on the reveal, fast on the release. Only one clip's texture updates at any time.

The station, pinned horizontal tour: pin the section and translate horizontally through the three environment plates as the visitor scrolls, each plate full-bleed with a short mono caption typing on as it centres — location designation, one line of what happened there. Give the plates a slight parallax against their captions so the move has depth, and let each plate's video play only while it's the centred one, paused otherwise. The pause at each plate should be long enough to read, short enough to never feel stuck.

Wishlist, the second and final use of green: a single full-viewport closing frame, near-empty — the game title small and high like a hull stamp, one line of copy, and one acid-green wishlist button that is the only fully saturated element on the entire page. When it enters, the green bleeds a soft glow that settles as the button comes to rest. Heat has falloff; a flat colour swap doesn't. No store badges, no platform logo grid — one link.

Video playback: only the hero is scrubbed. For it, do not set current time on a video element — it stutters badly and behaves differently in every browser. Extract each frame at around 15 frames per second, no wider than 1600px, save them as WebP, and draw the correct frame to a canvas based on scroll progress. An 8-second clip at that rate is around 120 frames — preload every one before the section becomes interactive, and keep the total weight of the sequence small enough to load quickly. The operative and environment clips are not scrubbed on scroll — keep them as ordinary video elements, muted, looping and preload auto, and lazy-load them as their sections approach. The operative hover scrub drives the video's frame via the same canvas technique only if testing shows video seeking stutters; otherwise map cursor position to playbackRate direction and let it run — say which approach you used in your final summary. There's no hover on touch, so on mobile play each operative's turn once as its row enters the viewport, and swap the hero frame sequence for a poster frame with the title. Under prefers-reduced-motion, the hero holds one well-chosen frame, the horizontal tour becomes ordinary vertical sections, and the page scrolls normally.

Keep it tight. Invent the game's name and write short, confident copy — a few words per headline, no filler paragraphs, no lorem. Build only the sections described here plus a minimal footer. Do not add testimonials, feature grids, pricing tables, FAQ accordions, newsletter signups, cookie banners, media galleries, system requirements tables or dead nav links. Empty space is part of the design.

Run this end to end. Do not ask me any questions. Make every remaining decision yourself — game name, operative callsigns, copy, exact hex values, file structure — and tell me what you chose at the end.

Stack is Vite with vanilla Javascript and GSAP. No React, no Next, no Tailwind, no component library. Use ffmpeg for any frame extraction and just run it, don't ask first.

When it's built, push it to a new GitHub repo and deploy it on Vercel. Assume the gh and vercel CLIs are already authenticated. If either isn't, finish the build, leave it running locally, and print the exact commands I need to run — don't stall the build waiting on it.
